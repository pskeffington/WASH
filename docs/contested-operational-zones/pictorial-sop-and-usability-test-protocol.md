# Pictorial Operating SOP and Usability-Test Protocol

## Purpose

This pass addresses the UNICEF-aligned requirement that emergency household water-treatment systems be easy and intuitive to operate. The goal is to verify that an unfamiliar responder can operate the alternative-water system correctly after brief instruction and can recognize when the system must not be used as validated drinking water.

This document defines:

1. a low-text pictorial operating sequence;
2. a standardized usability test;
3. pass/fail criteria for critical tasks;
4. redesign triggers when users make predictable errors.

The system remains a **TREATMENT RESEARCH ONLY** platform unless separately verified for a stronger use classification.

---

# 1. Core user tasks

An operator should be able to complete the following without expert intervention:

```text
1. INSPECT
2. COLLECT
3. FIRST FLUSH
4. STORE RAW WATER
5. TREAT
6. STORE CLEAN WATER
7. READ STATUS
8. DISPENSE OR STOP
9. CLEAN / RESET
10. REPORT A FAILURE
```

The SOP should avoid requiring users to understand the full engineering rationale in order to operate safely.

---

# 2. Pictorial sequence

Each physical module should carry a numbered symbol matching the system flow.

## STEP 1 — INSPECT

Suggested symbol:

```text
EYE + CHECK MARK
```

Operator checks:

- collector liner intact;
- no sewage/flood contact;
- no obvious oil/chemical contamination;
- barrel stand stable;
- status card present.

If any critical issue is present:

```text
STOP SYMBOL
→ DO NOT USE AS DRINKING WATER
```

---

## STEP 2 — PREPARE COLLECTION

Suggested symbol:

```text
CLOUD + RAIN
```

Actions:

- ensure catchment is clean enough for collection;
- confirm screen is installed;
- confirm first-flush device is reset;
- confirm raw storage inlet is connected.

Do not connect directly to clean storage.

---

## STEP 3 — FIRST FLUSH

Suggested symbol:

```text
DIRTY DROP → WASTE
```

Use one of two clearly labeled system types.

### FF-M1 — manual

1. rain begins;
2. dirty initial runoff goes to first-flush chamber/waste path;
3. operator confirms required first-flush volume is captured;
4. operator switches/diverts later runoff to raw storage.

### FF-F1 — floating-ball

1. chamber fills;
2. float closes first-flush path;
3. later runoff proceeds to raw storage;
4. operator verifies float actually seated.

Critical rule:

```text
FIRST FLUSH FAILED = DO NOT SEND WATER TO CLEAN/TREATED PATH
```

---

# 4. RAW STORAGE

Suggested symbol:

```text
BARREL + R
```

Raw storage should be marked with:

- large `RAW` text;
- distinct symbol;
- source/date tag;
- separate valve/fitting from clean storage.

Operator tasks:

- confirm lid closed;
- confirm vent screen intact;
- do not hand-dip;
- inspect for overflow or flood contact.

---

# 5. PRETREATMENT

Suggested symbol:

```text
SCREEN → SETTLE → FILTER
```

Operator should not need to adjust internal media during routine use.

Routine actions should be limited to:

- observe flow;
- observe turbidity;
- clean removable screen;
- drain settled solids when scheduled.

If media is disturbed:

```text
STATUS → GRAY
```

until recommissioned.

---

# 6. HEALTH-CRITICAL FILTER

Suggested symbol:

```text
FILTER + SHIELD
```

Operator checks:

- correct element installed;
- housing closed;
- seal/witness mark intact;
- flow within expected band;
- maintenance date current.

Critical visual rule:

```text
TOO FAST = POSSIBLE FAILURE
TOO SLOW = POSSIBLE CLOGGING
NO BASELINE = UNKNOWN STATUS
```

Do not teach users that “more flow is better.”

---

# 7. DISINFECTION

Suggested symbol:

```text
SHIELD + DROP
```

If disinfection is required:

- use only the approved method for that system;
- follow the validated product/device protocol;
- record completion;
- verify required operational parameter where applicable.

No pictorial card should invent a universal chlorine dose, boiling interval, UV exposure, or solar-disinfection duration.

---

# 8. CLEAN STORAGE

Suggested symbol:

```text
BARREL + C + CHECK
```

Clean storage should be physically and visually distinct from raw storage.

Operator checks:

- lid closed;
- vent screened;
- spigot clean;
- no raw cross-connection;
- status card current.

Water should leave clean storage only through controlled dispensing.

---

# 9. STATUS CARD

Suggested symbols:

```text
GREEN circle + check
AMBER triangle + !
RED stop sign
GRAY square + ?
```

## GREEN

```text
APPROVED FOR STATED USE
```

## AMBER

```text
RESTRICTED / TREATMENT REQUIRED
```

## RED

```text
DO NOT USE
```

## GRAY

```text
STATUS UNKNOWN
DO NOT ASSUME SAFE
```

Critical usability rule:

> users must understand that GRAY is not a weaker form of GREEN.

---

# 10. DISPENSING

Suggested symbol:

```text
CUP UNDER TAP
```

Before dispensing:

1. check status card;
2. verify clean outlet label;
3. confirm valve/spigot is clean;
4. use a clean receiving container.

If status is RED or GRAY for drinking use:

```text
OUTLET SHOULD BE CAPPED / LOCKED / HANDLE REMOVED
```

---

# 11. CLEAN / RESET

Suggested symbol:

```text
BRUSH + CIRCULAR ARROW
```

Routine tasks:

- clean screen;
- empty/reset first flush;
- inspect collector;
- check barrel lids and vents;
- inspect filter status;
- clear overflow area.

Invasive treatment maintenance automatically changes status to:

```text
GRAY
```

until recommissioning is complete.

---

# 12. REPORT FAILURE

Suggested symbol:

```text
WRENCH + EXCLAMATION
```

Operator should report:

- system ID;
- observed problem;
- current status color;
- last known normal operation;
- whether water was dispensed after failure was noticed.

Do not require a technical diagnosis from the operator.

---

# 13. One-page SOP layout

The final field card should fit on one waterproof page with 8-10 large panels.

Recommended layout:

```text
[1 INSPECT]     [2 PREPARE]
[3 FIRST FLUSH] [4 RAW STORAGE]
[5 FILTER]      [6 DISINFECT]
[7 CLEAN STORE] [8 CHECK STATUS]
[9 DISPENSE]    [10 STOP/REPORT]
```

Use arrows to show only the intended flow direction.

Raw and clean sides should not visually overlap.

---

# 14. Usability-test objective

Test whether an unfamiliar operator can safely operate the system after a short standardized orientation.

Do not coach during the test unless an immediate safety issue arises.

The test measures:

- comprehension;
- task completion;
- error rate;
- time to complete;
- recognition of critical failures;
- ability to use the status system.

---

# 15. Test participant profile

Prefer participants who are unfamiliar with the specific prototype.

Possible test groups:

- humanitarian responder;
- community health worker;
- utility worker;
- general adult household user;
- engineering/logistics staff not involved in design.

Avoid testing only with project developers.

---

# 16. Standardized orientation

Provide no more than a short briefing covering:

1. raw and clean water are separate;
2. follow the numbered picture card;
3. first flush must occur before raw storage collection;
4. status card controls whether drinking dispensing is allowed;
5. RED and GRAY are not drinking-water states.

Then hand the participant the SOP card and begin the test.

---

# 17. Baseline usability tasks

## U1 — identify raw vs clean storage

Pass:

participant correctly identifies both without opening system.

Critical fail:

participant selects raw storage as drinking outlet.

## U2 — prepare system for rain

Pass:

- screen checked;
- first flush reset;
- raw storage connected.

## U3 — operate first flush

Pass:

participant correctly routes initial runoff away from drinking-water pathway.

Critical fail:

participant intentionally or accidentally sends first-flush water to clean storage.

## U4 — identify treatment path

Pass:

participant follows raw → treatment → clean sequence.

## U5 — recognize abnormal filter condition

Simulate:

- broken seal;
- unusually high flow;
- missing status tag.

Pass:

participant does not continue normal drinking-water dispensing.

## U6 — interpret status card

Present GREEN, AMBER, RED, GRAY sequentially.

Pass:

participant correctly identifies whether drinking dispensing is allowed under the system-specific classification.

Critical fail:

participant treats GRAY as safe.

## U7 — respond to positive microbial result

Provide scenario card:

```text
FINAL WATER TEST: POSITIVE
```

Pass:

participant changes/recognizes RED state and locks/caps drinking outlet.

## U8 — maintenance state

Tell participant filter has just been opened/replaced.

Pass:

participant recognizes status must be GRAY until recommissioned.

## U9 — clean storage hygiene

Pass:

participant does not hand-dip and uses controlled outlet.

## U10 — report failure

Pass:

participant can state system ID, problem, status, and whether dispensing occurred.

---

# 18. Critical-error list

Any of the following is an automatic redesign trigger:

```text
CE-1 raw water dispensed as clean
CE-2 first-flush water sent to clean storage
CE-3 RED interpreted as drinkable
CE-4 GRAY interpreted as drinkable
CE-5 failed/broken filter ignored
CE-6 positive microbial result does not trigger lockout
CE-7 clean and raw hoses intentionally cross-connected
CE-8 drinking outlet reopened before recommissioning
```

A system that repeatedly produces these errors is not intuitive enough for field deployment.

---

# 19. Scoring

For each task:

```text
2 = correct without prompting
1 = correct after consulting card / minor hesitation
0 = incorrect or unsafe
```

Ten tasks:

```text
maximum = 20 points
```

Prototype target:

```text
>=18/20
AND
zero critical errors
```

This is an internal usability target, not a UNICEF requirement.

---

# 20. Time metric

Record:

- total orientation time;
- total task time;
- time to identify RED/GRAY state;
- time to lock out drinking outlet.

The objective is not raw speed. Excessive delay can reveal confusing controls or labeling.

---

# 21. Comprehension questions

After task completion ask:

1. Which barrel is raw water?
2. Which barrel is clean water?
3. What does GRAY mean?
4. What do you do if filter flow suddenly becomes much faster?
5. What happens after the filter is opened for maintenance?
6. Can clear-looking water be assumed safe?
7. Who do you tell if the system fails?

Do not correct answers until after scoring.

# 23. Redesign hierarchy

If users fail a task, modify the hardware/interface before adding more text whenever possible.

Preferred order:

```text
1. PHYSICAL SEPARATION
2. CONNECTOR DIFFERENTIATION
3. VALVE / HANDLE POSITION
4. SYMBOL / COLOR / SHAPE
5. SHORT WORDING
6. LONGER INSTRUCTION
```

A system that requires a long manual to prevent a common dangerous error is not sufficiently intuitive.

---

# 24. Multilingual / low-literacy requirements

The field SOP should:

- use icons plus words;
- avoid dense paragraphs;
- use arrows consistently;
- keep raw and clean symbols distinct;
- use numbers for sequence;
- avoid color-only meaning;
- be locally translated;
- field-test translations with actual users.

Translation should preserve the operational meaning of:

```text
RAW
CLEAN
TREATMENT REQUIRED
DO NOT USE
STATUS UNKNOWN
```

---

# 25. Human-factors design freeze

Freeze the following for the integrated prototype:

```text
1. RAW and CLEAN must be visually and physically distinct.
2. Process flow must be one-directional in diagrams and hardware.
3. GREEN / AMBER / RED / GRAY status must appear at the dispensing point.
4. RED and GRAY drinking outlets must support physical lockout.
5. First-flush state must be externally visible.
6. Routine operation should not require opening treatment housings.
7. Maintenance automatically changes status to GRAY.
8. Abnormal high flow must be taught as possible failure.
9. No operator should need to infer drinking safety from water clarity.
10. Critical errors in usability testing trigger redesign before deployment.
```

---

## WHO / UNICEF alignment

This usability protocol supports the practical implementation of WHO Water Safety Plan risk controls and UNICEF emergency HWTS objectives for systems that are intuitive, fail-safe or fail-visible, durable, and suitable for emergency use.

The focus is not only whether the treatment technology can work in laboratory conditions. It is whether the complete household system can be **used correctly and consistently by the intended operator**.
